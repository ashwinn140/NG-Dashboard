GETTING STARTED

Help & User Guide

A practical guide to reading the dashboard, applying filters, understanding dates and checking the source behind each metric. The metric dictionary below is loaded from the same permission-aware definitions used by the dashboard.

Important: A calculation marked code-verified means the implementation and source mapping are documented in the application. It does not, by itself, mean every historical source file or production row has been independently reconciled.

1. Your access scope

Your login determines which companies, lines of business and financial information you can see. Access is enforced by the server, not just by hiding dashboard controls.

  • Company and LOB filters can only narrow your permitted data.
  • Finance metrics and financial exports require finance permission.
  • Exports use the same server-side access scope as the page.

2. Filters and selections

Different filter dimensions work together using AND. Multiple values selected within one dimension work using OR.

  • Search supports partial text matching where the selector provides it.
  • Clear a single filter to broaden that dimension; Reset clears the current selection.
  • A visual click may filter the rest of the dashboard. Use the clear/reset controls to return to the broader view.

3. Reporting dates

Operations: shipment activity is based on Shipment Date.

Finance: income, expense and booked GP are based on Job Date from the simple Job Profit Analysis Report.

Job Date is not Billing Date. Do not interpret it as the invoice date.

4. Comparisons and percentages

Comparison views show the actual current and comparison periods. Previous-period comparisons may use an equal-length preceding window; YoY and fiscal-year comparisons follow their selected basis.

  • A zero prior-period baseline has no mathematically valid percentage change.
  • Negative baselines use the absolute prior value as the percentage denominator.
  • Missing history is not the same as zero activity.

5. Customer & Partner 360

Use relationship filters to explore customers, shippers, consignees, agents, locations, branches and sales attribution.

  • Relationship activity is a review signal, not confirmation that a customer is lost.
  • Cross-LOB context uses only the shipment-register rows currently loaded and visible to your login.
  • Customer matching is source-name based where a verified ERP customer code is not available. Similar names are not automatically merged.

6. Last five jobs and Job Owner

Operations → Customers provides a View jobs action where available. It shows up to five recent distinct JPR jobs for the selected customer within your permitted company/LOB scope.

  • Job identity: company + LOB + Job No. + Job Date.
  • Owner is taken from the JPR source. Missing or conflicting owner values are shown as unavailable rather than guessed.
  • History reflects the currently loaded JPR snapshot; it is not an all-time guarantee beyond loaded history.

7. Booked and estimated finance

Booked GP is Income less Expense from the accepted simple JPR. A zero recorded expense does not prove that no cost was incurred.

  • Expected missing cost is a separately identified estimate, not a booked cost or liability.
  • Rate-based freight margin is an estimate from eligible matched rate rows, not necessarily ledger GP.
  • Use the metric explanation and evidence action before interpreting an exception count.

8. Exports and evidence

Use the page's export action to download the selected view. Financial values are omitted for users without finance access.

  • Calculation & records opens the evidence behind supported metrics.
  • Evidence is bound to the dataset snapshot and the filters used for the visual.
  • Missing source values remain unavailable; they are not silently converted to zero unless the metric definition explicitly says so.
